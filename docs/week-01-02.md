## 2. What a database is

A **database** stores data so it survives restarts and can be searched. It holds **tables**. A table
is like one Excel sheet: **columns** are the kinds of facts, **rows** are the records.

This site's announcements table, `backend/app/models_teacher.py:104`:

```python
class Announcement(Base):
    __tablename__ = "fde_announcements"
    id: Mapped[int] = mapped_column(primary_key=True)   # unique number, picked by the database
    title: Mapped[str] = mapped_column(String(200))
    body: Mapped[str] = mapped_column(Text, default="")
    week_id: Mapped[str | None] = ...
    pinned: Mapped[bool] = ...
    created_by: Mapped[int] = mapped_column(ForeignKey("fde_users.id"))  # points at a user row
    author_name: ...
    created_at: ...
```

As a table it looks like this:

| id | title | body | week_id | pinned | created_by | author_name | created_at |
|---|---|---|---|---|---|---|---|
| 1 | Hello from curl | This row was added by a POST | week-01 | false | 1 | Demo Teacher | 2026-11-17 14:07 |

The code never writes SQL by hand. **SQLAlchemy** (an ORM) turns Python objects into SQL. The
connection is made once in `backend/app/db.py:25` (`engine = ...`), and each request gets its own
**session** from `get_db()` at `backend/app/db.py:29`. Tables are created at start-up by `init_db()`
(`backend/app/db.py:37`).

## 3. CRUD

CRUD is the four things you can do with stored data. Each one is an HTTP method on the API and a SQL
command in the database. Announcements do all four, in `backend/app/teacher.py`:

| CRUD | HTTP method | SQL | This site | Line |
|---|---|---|---|---|
| **C**reate | `POST` | `INSERT` | `POST /teacher/announcements` → `post_announcement` | `teacher.py:888` |
| **R**ead | `GET` | `SELECT` | `GET /announcements` → `announcements` | `teacher.py:882` |
| **U**pdate | `PATCH` (or `PUT`) | `UPDATE` | `PATCH /teacher/announcements/{id}` → `edit_announcement` | `teacher.py:899` |
| **D**elete | `DELETE` | `DELETE` | `DELETE /teacher/announcements/{id}` → `delete_announcement` | `teacher.py:911` |

`PUT` vs `PATCH`: both update. `PUT` usually means "set it to exactly this, create it if missing",
like `PUT /weeks/{week_id}/projects/{project_id}/submission/{field_id}` at `backend/app/api.py:182`,
which updates the saved link if there is one and adds a row if not. `PATCH` means "change this
existing thing".

Your P1 is the same idea with a `calls` table: `POST /calls` creates, `GET /calls` reads.

## 4. Every part of a request and its reply

```
POST https://fde-learnings.onrender.com/api/fde/teacher/announcements      ← method + URL
Content-Type: application/json                                              ← header
Authorization: Bearer eyJhbGciOi...                                         ← header (your token)

{"title": "Hello from curl", "week_id": "week-01"}                          ← body (JSON)
```

| Part | What it is | Example on this site |
|---|---|---|
| **Method** | The verb: what you want done | `GET` reads, `POST` creates, `PATCH`/`PUT` update, `DELETE` removes |
| **Base URL** | Where the API lives | `https://fde-learnings.onrender.com/api/fde` |
| **Path** | Which door (route) | `/weeks/week-01` |
| **Path parameter** | A value inside the path that picks one thing | `week-01` in `/weeks/{week_id}` (`backend/app/api.py:93`) |
| **Query parameter** | Options after `?`, mostly with GET, to filter | `/voice-quiz/leaderboard?week_id=week-02` (`backend/app/voice.py:191`: `week_id: str \| None = None` means "optional query parameter") |
| **Headers** | Labelled extra details | `Content-Type: application/json`, `Authorization: Bearer <token>` |
| **Body** | The data, as JSON | `{"title": "Hello"}`. Its shape is checked by `AnnouncementIn` (`teacher.py:870`) |

The reply has a **status code**, headers and usually a body:

| Code | Meaning | When this site sends it (all seen in a real run) |
|---|---|---|
| 200 OK | It worked | `GET /announcements` with a token → `{"announcements": [...]}` |
| 201 Created | A new row was saved | `POST /teacher/announcements` → the new row with its `id` |
| 401 Unauthorized | No token, or a bad one | `GET /announcements` without the header → `{"detail":"Please log in again."}` |
| 403 Forbidden | Signed in but not allowed | An email outside the allowed domain |
| 404 Not Found | No such thing | `GET /weeks/week-09` → `{"detail":"That week isn't available yet."}`. Teacher routes also say 404 to non-teachers, so they can't tell the page exists |
| 422 Unprocessable | The body failed the check | POST without a `title` → `{"detail":[{"type":"missing","loc":["body","title"],...}]}` |
| 500 Server Error | The server broke | A bug or the database is down |

Rule of thumb: **2xx** worked, **4xx** fix your request, **5xx** the server's problem.

Where the page builds these requests: `frontend/src/api.js:15`. It adds `Content-Type: application/json`,
adds `Authorization: Bearer <token>` (line 19) from the browser's `localStorage` key `fde.token`
(line 2), and turns the body into JSON. To watch it, open the site, press F12, open the **Network** tab
and click around: every row is one request with its method, URL, headers, body and status code.

## 5. How one API call changes the database, step by step

Follow `POST /teacher/announcements` from your terminal to the home page:

1. **You send it.** curl (or the Teach page's "Post" button, `frontend/src/pages/Teach.jsx:74`) sends
   `POST` with a token header and a JSON body.
2. **Render receives it** and hands it to **Uvicorn**, the program that runs the FastAPI app.
3. **The router matches it.** FastAPI finds the function marked `@router.post("/teacher/announcements")`
   at `backend/app/teacher.py:888`.
4. **The body is checked.** Pydantic compares it with `AnnouncementIn` (`teacher.py:870`): `title`
   1–200 characters, `body` optional, `week_id` optional, `pinned` true/false. Wrong shape → **422**,
   and nothing touches the database.
5. **You are checked.** `require_teacher` (`teacher.py:84`) uses `current_user`
   (`backend/app/security.py:43`) to read and verify the token. No token → **401**. Not a teacher → **404**.
6. **A database session opens.** `get_db()` (`backend/app/db.py:29`) gives the function `db`.
7. **The row is written.** `db.add(a)` stages a new `Announcement`; `db.commit()` makes SQLAlchemy send
   `INSERT INTO fde_announcements (...) VALUES (...)` to Postgres on Neon. Postgres saves it and picks the next `id`.
8. **The reply goes back:** **201 Created** with the saved row as JSON.
9. **The page reads it.** The home page calls `GET /announcements` when it loads
   (`frontend/src/pages/Home.jsx:54`). That runs `SELECT ... FROM fde_announcements ORDER BY pinned, id DESC LIMIT 20`
   (`teacher.py:882`) and draws each row (`Home.jsx:112`). Refresh, and your row is there.

Update and delete are the same path with `db` changing (`a.title = ...`) or removing (`db.delete(a)`)
the row before `db.commit()`. A `GET` never calls `commit()`, so it never changes anything.

## 6. Server, service and service layer

- **Server**: the computer and program that wait for requests and answer them. Render's computer
  runs Uvicorn, which runs the FastAPI app.
- **Service**: one running program with one job, used by others. On Render this API is a "web service".
  Neon is a database service, LiveKit a voice service.
- **Service layer**: in bigger apps, the route stays thin and calls a "service" function that holds
  the business rules, which then calls the database (route → service → database).
  This site is small, so most routes do the work themselves (check, add the row, commit). A few shared
  helpers play the service role, for example `queue_for_submission` (`backend/app/grading.py:221`),
  which the submission route calls to start auto-grading.

### Try it on this site (live)

The first request after a quiet spell takes up to a minute while Render's free plan wakes up.

1. Public, no sign-in (a GET, so nothing changes):
   ```bash
   curl https://fde-learnings.onrender.com/health
   # {"ok":true}
   curl https://fde-learnings.onrender.com/api/fde/weeks
   # [{"id":"week-01","number":1,"title":"Programming fundamentals",...},{"id":"week-02",...}]
   ```
2. Get your token. Sign in at https://fde-learning-rho.vercel.app with Google, press F12, open
   **Console**, and run `localStorage.getItem("fde.token")`. Copy the text (without quotes). It is
   like a password for a few hours: don't paste it anywhere public.
   ```bash
   export TOKEN='paste-it-here'
   ```
3. **Read** (R): what's there now.
   ```bash
   curl https://fde-learnings.onrender.com/api/fde/announcements -H "Authorization: Bearer $TOKEN"
   # {"announcements":[...]}
   ```
4. **Create** (C): add a row. You need to be a teacher or the admin.
   ```bash
   curl -i -X POST https://fde-learnings.onrender.com/api/fde/teacher/announcements \
     -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"title": "Hello from curl", "body": "This row was added by a POST", "week_id": "week-01"}'
   # HTTP/1.1 201 Created
   # {"id":1,"title":"Hello from curl","body":"This row was added by a POST","week_id":"week-01","pinned":false,"author":"...","created_at":"..."}
   ```
5. **See it on the page**: refresh https://fde-learning-rho.vercel.app. The announcement is at the top
   of the home page. That is the P1 "Done when" in action: a curl POST added a row, the React page shows it.
6. **Update** (U), using the `id` from step 4:
   ```bash
   curl -X PATCH https://fde-learnings.onrender.com/api/fde/teacher/announcements/1 \
     -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
     -d '{"title": "Hello again", "body": "Edited with PATCH", "pinned": true}'
   ```
7. **Delete** (D), to clean up:
   ```bash
   curl -X DELETE https://fde-learnings.onrender.com/api/fde/teacher/announcements/1 -H "Authorization: Bearer $TOKEN"
   # {"ok":true}
   ```
8. See the errors on purpose: drop the `-H "Authorization..."` line (**401**), or send `-d '{"body": "no title"}'` (**422**).
9. A query parameter: `curl "https://fde-learnings.onrender.com/api/fde/voice-quiz/leaderboard?week_id=week-02" -H "Authorization: Bearer $TOKEN"`.

The outputs above are from a real run of the same commands against the API on a laptop
(`uvicorn app.main:app` with a SQLite file); the live site returns the same shapes.

## 9. Dictionary

Every technical word used in weeks 1–2, in one line each. The same list is the "Dictionary" lesson
on the site (concept `glossary` in `content/week-01.json`); change both together.

| Word | Meaning |
|---|---|
| **201 Created / 200 OK** | Success codes. 201 means a new row was saved; 200 means it worked. |
| **401 / 403 / 404 / 422** | 401 no or bad token; 403 signed in but not allowed; 404 no such thing (this site also says 404 to hide teacher pages); 422 the body failed the check. |
| **API** | Application Programming Interface: a list of doors (addresses) a program opens so other programs can ask it for things. This site's API lives at fde-learnings.onrender.com/api/fde. |
| **Authentication** | Proving who you are, for example signing in with Google. |
| **Authorization** | What you are allowed to do once you are known. A learner can read announcements; only a teacher can add one. |
| **Authorization header** | The header that carries your token: Authorization: Bearer <token>. |
| **Backend** | The part of an app that runs on a server: it checks requests, does the work and talks to the database. Here: the FastAPI code in backend/. |
| **Base URL** | The start of every address an API uses, such as https://fde-learnings.onrender.com/api/fde. Each route adds its own path after it. |
| **Bearer token** | A token you send in the Authorization header. Whoever holds (bears) it is treated as you, so keep it private. |
| **Body** | The data sent with a request or a reply, usually JSON. POST, PUT and PATCH carry a body; GET and DELETE usually don't. |
| **Client** | Whoever sends the request: a browser, curl, Postman or another server. |
| **Column** | One kind of fact in a table, such as title or created_at. Every row has a value for each column. |
| **Commit (database)** | The moment changes are saved for good. Until db.commit() runs, nothing is really written. |
| **CORS** | A browser rule: a page may only call an API that lists the page's address as allowed. Set by CORS_ORIGINS on the API. |
| **CRUD** | Create, Read, Update, Delete: the four things you can do with stored data. They map to POST, GET, PUT or PATCH, and DELETE. |
| **curl** | A command-line tool that sends one HTTP request and prints the reply. Same job as Postman, but typed. |
| **Database (DB)** | A program that stores data safely and lets you search it. Here: Postgres on Neon online, a SQLite file on your laptop. |
| **DELETE** | HTTP method that removes something. The D in CRUD. |
| **Deploy** | Putting your code on a host so it runs on a public address instead of only your laptop. |
| **DevTools** | The browser's built-in tools (right-click, Inspect). The Network tab shows every API call the page makes. |
| **Endpoint / route** | One door of an API: a method plus a path, such as POST /teacher/announcements. |
| **Environment variable (env var)** | A setting given to a program from outside its code, such as DATABASE_URL. Keys live here, never in code. |
| **FastAPI** | The Python framework this site's backend is written in. You write a function and mark it with @router.get or @router.post. |
| **Foreign key** | A column that points at a row in another table, such as created_by pointing at fde_users.id. |
| **Frontend** | What people see and click: the React page, served by Vercel. |
| **GET** | HTTP method that reads. It should never change data. The R in CRUD. |
| **Header** | A small labelled detail sent with a request or reply, such as Content-Type: application/json or Authorization. |
| **Host** | A company whose computers run your code: Render (API), Vercel (page), Neon (database), LiveKit Cloud (voice bot). |
| **HTTP** | The language browsers and servers use to talk: a request goes out, a reply comes back. HTTPS is the same, encrypted. |
| **HTTP method** | The verb of a request: GET, POST, PUT, PATCH or DELETE. |
| **id / primary key** | A column whose value is unique for each row, so one row can be found exactly. The database picks it on insert. |
| **INSERT, SELECT, UPDATE, DELETE (SQL)** | The four SQL commands behind CRUD. SQLAlchemy writes them for you. |
| **Interruption (barge-in)** | When the caller speaks over the bot. With interruptions on, the bot stops talking and listens. |
| **JSON** | A plain-text way to write data: {"title": "Hello", "pinned": false}. APIs send and receive it. |
| **JWT** | JSON Web Token: the signed token this site gives you when you sign in. The API checks the signature on every request. |
| **LLM** | Large Language Model: the brain of a voice bot that writes the reply text. |
| **localhost** | Your own computer. http://localhost:8000 only works on your laptop. |
| **localStorage** | A small store inside the browser. This site keeps your token there under the key fde.token. |
| **ORM** | Object-Relational Mapper: lets you work with rows as Python objects. This site uses SQLAlchemy. |
| **PATCH** | HTTP method that changes part of something that already exists. The U in CRUD. |
| **Path** | The part of the URL after the host, such as /api/fde/weeks/week-01. |
| **Path parameter** | A value written inside the path, such as week-01 in /weeks/{week_id}. It picks which thing you mean. |
| **Payload** | Another word for the body. |
| **POST** | HTTP method that creates something new. The C in CRUD. A good API replies 201 Created. |
| **Postgres** | A popular SQL database. Neon runs it for this site. |
| **Postman** | An app for sending API requests with buttons instead of typing curl. |
| **PUT** | HTTP method that sets something to a given value, creating it if missing. The U in CRUD. |
| **Pydantic** | The Python library FastAPI uses to check a request body. A missing or wrong field gets a 422 reply. |
| **Query parameter** | Extra options after a ? in the URL, such as ?week_id=week-02. Used to filter or sort, mostly with GET. |
| **Request** | What the client sends: method, URL, headers and maybe a body. |
| **Response / reply** | What the server sends back: a status code, headers and usually a body. |
| **REST** | A common style of API: things are nouns in the path (/announcements) and the method says what to do with them. |
| **Router** | The part of FastAPI that matches a method and path to the Python function that handles it. |
| **Row** | One record in a table, such as one announcement. |
| **Schema** | The shape data must have: which fields, which types, which are required. |
| **Server** | A computer (or program) that waits for requests and answers them. Uvicorn is the server program here; Render's computer runs it. |
| **Service** | A running program that does one job for others. On Render, this API is a 'web service'. LiveKit is a voice service. |
| **Service layer** | In bigger apps, the code between the route and the database that holds the business rules. This site is small, so most routes talk to the database themselves. |
| **Session (database)** | One conversation with the database inside one request. get_db() opens it and closes it after the reply. |
| **SQL** | Structured Query Language: the language databases understand, such as SELECT * FROM fde_announcements. |
| **SQLAlchemy** | The Python library (an ORM) this site uses to talk to the database. |
| **SQLite** | A database that is a single file. Used on your laptop when DATABASE_URL is blank. |
| **Status code** | The 3-digit number at the top of a reply. 2xx worked, 4xx your request is wrong, 5xx the server broke. |
| **STT** | Speech-to-text: the ears of a voice bot. |
| **Table** | A grid of rows and columns, like one sheet in Excel. This site's tables start with fde_, such as fde_announcements. |
| **Token** | A string that proves you are signed in. Send it in the Authorization header. |
| **TTS** | Text-to-speech: the mouth of a voice bot. |
| **Turn detection / endpointing** | How a voice bot decides you have finished speaking. Wait too little and it cuts you off; too long and it feels slow. |
| **URL** | A full web address: https:// + host + path + optional ?query. |
| **Uvicorn** | The program that runs the FastAPI app and listens for HTTP requests. |
| **VAD** | Voice Activity Detection: spots when someone is speaking at all. This site's bot uses Silero VAD. |
| **Webhook** | An API call one server makes to another when something happens, such as 'the call ended'. Week 3 joins P1 and P2 this way. |
